Span APIs

Use the Span Metrics API for time-series aggregates and the Span Analytics API for filtered span counts, grouped breakdowns, tag summaries, and example spans. Both APIs run asynchronous jobs that you submit and poll.

JSON over HTTPSPOST · GET · DELETEOrganization scoped
For platform integrations

Send requests through the approved Splunk Observability API gateway for your environment. The API derives the organization context from the authenticated request; do not pass an organization ID in the request body. The cURL examples use $APM_API_BASE and $AUTH_HEADER as environment-specific placeholders; set AUTH_HEADER to one complete header line accepted by your gateway.

Start here

Before making a request, confirm that the target organization has Span Analysis enabled and that your integration uses the supported gateway and credentials for that environment.

1Choose an APIMetrics for a single time series; Analytics for section-based queries and span examples.
2Submit a jobPOST a JSON body. Keep the returned jobId.
3Poll or cancelGET the job until complete. DELETE it to cancel work you no longer need.
Access is feature gated

Both resources check the per-organization spanAnalysisEnabled setting. The code documents this setting as disabled by default. A disabled organization receives HTTP 403.

Request context

At the API service, the authenticated request must include the user and organization identity supplied by the trusted gateway. The service reads X-SF-UserId and X-SF-OrgId; integrations should not set these identity headers themselves. Confirm the gateway's client authentication method and route with the API owner for the target environment.

Job lifecycle

These endpoints return data as a job progresses. A poll can contain partial results. Keep polling with the same job ID until the response reports completion, or cancel the job when the result is no longer needed.

ActionMetricsAnalytics
SubmitPOST /api/v2/apm/span-metricsPOST /api/analytics/span
PollGET /api/v2/apm/span-metrics/{jobId}GET /api/analytics/span/{jobId}
CancelDELETE /api/v2/apm/span-metrics/{jobId}DELETE /api/analytics/span/{jobId}

Metrics response

A job payload wraps the result in data and includes jobId, processed, and total.

Analytics response

A success envelope contains result, with jobId and a list of independently progressing sections.

Span Metrics API

Returns one aggregated span time series for the requested time range and filters. The server chooses a bucket granularity and returns that choice in the response.

POST/api/v2/apm/span-metrics

Submit a metrics query

cURL · submit
curl --request POST "$APM_API_BASE/api/v2/apm/span-metrics" \
  --header "Content-Type: application/json" \
  --header "$AUTH_HEADER" \
  --data '{
    "timeRangeMillis": {"gte": 1735689600000, "lt": 1735693200000},
    "environment": "prod",
    "serviceName": "checkout",
    "operationName": "POST /orders",
    "isErrorOnly": false,
    "bucketsPerQuery": 3
  }'

Time bounds use epoch milliseconds. The start bound is inclusive and the end bound is exclusive. Replace the sample timestamps and filters with values from your request.

Request fields

FieldTypeMeaning
timeRangeMillisrange objectRequired. Must have both lower and upper bounds, and start must precede end.
environmentstringOptional environment filter. Omit to include all environments.
serviceNamestringOptional service filter. Omit to include all services.
operationNamestringOptional operation filter. Omit to include all operations.
tagsarrayOptional tag predicates. A predicate has tag or scopedTagName, operation, and values.
tagsFilterTypeenumMATCH_ALL or MATCH_ANY; defaults to MATCH_ALL.
durationMicrosrange objectOptional duration filter. Values are microseconds; provide at least one bound.
isErrorOnlybooleanWhen true, include only spans with OpenTelemetry error status. Defaults to false.
bucketsPerQuerypositive integerOptional query window size in chart buckets; defaults to 3.

Poll for results

cURL · poll
curl --request GET "$APM_API_BASE/api/v2/apm/span-metrics/$JOB_ID" \
  --header "$AUTH_HEADER"

Read the metrics result from data. The response has an outer job envelope and an inner time-series result.

Response fields

JSON pathTypeMeaning
jobIdstringJob identifier. Also repeated inside data.jobId.
processedintegerCompleted query windows.
totalintegerTotal query windows for the job.
data.isCompletebooleanTrue when the requested range has finished processing.
data.granularityMinutesintegerResolved bucket width, in minutes.
data.seriesKeystringSeries identity, assembled from the requested environment, service, and operation filters.
data.dataPoints[]arrayChronological bucket values. See the fields below.
data.confirmedFromMsinteger · optionalStart-inclusive boundary of the completed, stable portion of the range. Reaches the request start when complete.
timeRange, processingRangeobject · optionalJob progress metadata when present.
completedProcessingItems, totalItemsToProcessintegerLegacy aliases for processed and total.

Fields in each dataPoints[] item

FieldTypeMeaning
bucketMsintegerBucket start time as Unix epoch milliseconds.
spanCountintegerNumber of spans in the bucket.
errorCountintegerNumber of error spans in the bucket.
errorRationumbererrorCount / spanCount; zero when the bucket has no spans.

While a query is running, confirmedFromMs marks the start of the completed portion of the requested range. Buckets from that timestamp through the request end are stable on later polls. When the job is complete, the confirmed boundary reaches the requested start.

DELETE/api/v2/apm/span-metrics/{jobId}

Cancel an active metrics job. The endpoint returns HTTP 204 when cancellation is accepted. Repeating a cancel for an unknown or already cancelled job is also treated as successful.

Span Analytics API

Runs one analytics job with one or more requested sections. A section is a requested result shape, such as a time bucket series or grouped breakdown. Common filters and the time range are shared across the sections in that job.

POST/api/analytics/span

Submit analytics sections

cURL · submit a count and group breakdown
curl --request POST "$APM_API_BASE/api/analytics/span" \
  --header "Content-Type: application/json" \
  --header "$AUTH_HEADER" \
  --data '{
    "sharedParameters": {
      "timeRangeMillis": {"gte": 1735689600000, "lt": 1735693200000},
      "samplingFactor": 100,
      "filters": []
    },
    "sectionsParameters": [
      {"sectionType": "spanCountTimeBucketed", "isErrorOnly": false},
      {
        "sectionType": "spanGroupBy",
        "groupBy": [{
          "alias": "service",
          "source": {"id": "service_name", "entity": "span", "sourceType": "property"}
        }],
        "orderBy": "spanCount",
        "direction": "desc"
      }
    ]
  }'

The successful response wraps data in result. Use result.jobId to poll; each result section reports its own completion state, so one section may finish before another.

GET/api/analytics/span/{jobId}DELETE/api/analytics/span/{jobId}

GET returns the current analytics envelope. DELETE aborts the analytics job. Analytics failures are represented in an analytics error envelope; check the response body as well as the HTTP status.

Shared request fields

FieldMeaning
sharedParameters.timeRangeMillisQuery range in epoch milliseconds. Use explicit bounds for predictable requests.
sharedParameters.samplingFactorOptional sample control. If omitted, the server uses its configured no-sampling default.
sharedParameters.filtersShared filters. Span and trace filters use filterType values spanFilter and traceFilter.

Analytics sections

These are the span-specific section types currently registered by the API.

Section typeUseKey request fields
spanCountTimeBucketedCount spans across time buckets.isErrorOnly (optional)
spanGroupByBuild a ranked hierarchical breakdown over span dimensions.groupBy (1–3 span dimensions), required orderBy, optional direction (default desc), isErrorOnly
spanTagStatSummarize one numeric or categorical span tag/property.required tag source, optional isErrorOnly

Group-by dimensions

A group source identifies a dimension with id, entity, and sourceType. Span group-by sources must use entity: "span"; source types are tag, property, or computed. Use an alias when a dimension needs a stable name in the response or drill-down context.

Supported sort values are spanCount, errorCount, durationP50Ms, durationP95Ms, and durationP99Ms. Direction is asc or desc.

Span examples limits

Historical query

Default limit is 100; maximum is 1,000.

Live tail

Default limit is 25; maximum is 50. Grouping is not supported for live-tail queries.

When using groupContext to drill into a group, its limit is capped at 25 and its group-by path must align with the selected group dimensions.

Errors and status codes

Metrics uses HTTP errors for request validation and job access. Analytics returns a typed error envelope for many query failures, so clients should parse its body instead of relying only on the HTTP status.

HTTP statusTypical meaningClient action
202Metrics job accepted.Read the job ID and start polling.
400Invalid request, such as a missing metrics range bound.Correct the request before retrying.
401Required authenticated organization context is missing.Check gateway authentication and identity propagation.
403Span Analysis is disabled for the organization.Ask the service owner to enable the per-org feature.
404Job ID is unknown or inaccessible.Verify the job ID and use the same org/user context.
410Metrics job expired or was cancelled.Submit a new job if results are still needed.
503Service or query failure surfaced as unavailable.Retry according to your integration's backoff policy.

The metrics API maps client-visible job failures to their 4xx status; analytics error responses can use a successful HTTP exchange with an error envelope. Do not assume every failed analytics request is indicated by a non-2xx code.

Data semantics

  • Metrics timestamps and timeRangeMillis are epoch milliseconds. Duration filters use microseconds; returned percentile values use milliseconds.
  • isErrorOnly means spans with OpenTelemetry error status.
  • Metrics returns one series per request. Grouping across multiple values is provided by the Analytics spanGroupBy section.
  • Analytics sections can complete independently. Preserve section-level completion and processing-range metadata when presenting partial data.
  • Job IDs are scoped to the authenticated caller context. Poll and cancel using the same org/user identity as the submit request.

Limits and client guidance

  • Always poll with a bounded interval and backoff; avoid tight loops.
  • Send only the sections needed for the current result. A single analytics job can contain multiple sections, which share its range and filters.
  • Set explicit time bounds, keep cancellation available, and treat partial results as partial until their completion fields say otherwise.
  • Validate all group-by sources against the API's span entity requirement and keep the group-by list to at most three dimensions.

Scope and implementation status

This page covers the implemented Span Metrics and Span Analytics resources: /api/v2/apm/span-metrics and /api/analytics/span, including their polling and cancellation routes.

Group trends endpoint

A separate group-trends API design exists in the repository as a proposal. It is not listed here as an available endpoint because the current API resource does not implement it.
